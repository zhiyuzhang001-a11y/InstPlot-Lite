# InstPlot Lite UI 改造计划

## 1. 目的

本轮 UI 改造的目标是在**不改变任何功能、数据结果和窗口规则**的前提下，
让 InstPlot Lite 更简洁、清晰、高效，并建立以后可以持续复用的界面规范。

设计方向参考 Apple Human Interface Guidelines，但不复制 macOS 控件外观，
也不把应用改成只适合 macOS 的界面。最终界面应同时适用于 Windows、
Apple Silicon macOS 和 Linux。

核心方向：

- 绘图区是主角，应用框架尽量安静。
- 高频功能容易发现，低频功能不过度占用工具栏。
- 相同类型的按钮、输入框、下拉框和窗口使用一致的尺寸与间距。
- 小窗口、窄窗口、最大化和系统全屏下都能访问全部功能。
- 用户已有的操作习惯、按钮含义和数据工作流保持不变。

参考资料：

- [Apple：Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)
- [Apple：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)
- [Apple：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- [Apple：Windows](https://developer.apple.com/design/human-interface-guidelines/windows)
- [Apple：Panels](https://developer.apple.com/design/human-interface-guidelines/panels)
- [Apple：Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- [Apple Grapher 用户指南](https://support.apple.com/guide/grapher/welcome/mac)

## 2. 成功标准

UI 改造完成后应达到以下结果：

1. 主界面的按钮分组、尺寸、基线和间距一致。
2. 左侧数据栏不会因长文件名挤压绘图区。
3. 绘图区在常见窗口尺寸下保持合理比例，坐标标题和状态栏不重叠。
4. 数据处理、曲线拟合和数据导出窗口使用统一的外壳和排版规则。
5. 所有工具窗口在尺寸较小时都能滚动并访问完整内容。
6. 下拉框、输入框、菜单和滚动区域不会被父区域裁剪或阻止操作。
7. Windows 最大化、macOS 系统全屏及普通窗口模式继续遵守现有规则。
8. 多个工具窗口可以同时打开、移动、置顶和独立关闭。
9. 字母、数字、公式和正文继续使用正常字号，不通过缩小文字解决布局问题。
10. 自动测试、导入导出结果、处理结果、拟合结果和更新器行为保持不变。

## 3. 明确不做的事情

本轮不进行以下修改：

- 不改变数据处理、拟合、导入、导出或更新算法。
- 不增加、删除或重命名功能。
- 不改变按钮对应的 Action 和执行顺序。
- 不改变默认参数、默认列、默认作用范围或覆盖/保留规则。
- 不改变窗口、绘图区、曲线、拟合和滚动区域的稳定 ID。
- 不更换 egui，也不引入另一套 UI 框架。
- 不仿制 Liquid Glass，不大量增加透明、模糊、动画或阴影。
- 不直接使用仅适合 Apple 平台的图标资源制作跨平台安装包。
- 不在 UI 改造过程中顺便修改已知或新发现的业务缺陷。
- 不在用户确认最终界面前发布 Release。

## 4. 必须保持的功能不变量

### 4.1 数据和操作

- TXT、CSV、DAT、TSV、XLSX 和 XLS 的导入行为不变。
- 多文件、多分区和多工作表的显示规则不变。
- 导入新文件时优先沿用已有同名 X/Y 列的规则不变。
- 公式中的 `x` 修改 X、`y` 修改 Y 的规则不变。
- 分数、括号、函数和参数表达式支持不变。
- 数据处理的覆盖原列/保留派生列规则不变。
- 多选处理和多选拟合规则不变。
- 同一目标重新拟合只替换对应旧拟合的规则不变。
- 撤销和重做继续以一次完整操作为一个历史步骤。
- 五种数据导出格式及重新导入闭环不变。

### 4.2 绘图和状态

- 主绘图区 ID 保持不变。
- 原始曲线、点和拟合曲线的系列 ID 保持不变。
- 图例点击继续同时控制线和数据点的显示与隐藏。
- 隐藏曲线不能因处理、拟合、撤销、重做或布局变化重新出现。
- 滚轮缩放、右键平移、左键点选、吸附和框选删除规则不变。
- 坐标轴科学计数法、偏移量和精度规则不变。
- PNG 导出范围和白底图像内容不因应用外壳改造而改变。

### 4.3 工具窗口

- 数据处理、曲线拟合和数据导出继续使用三个不同的稳定窗口 ID。
- 任意系统的真正全屏继续使用嵌入式工具窗口。
- Windows 主窗口最大化继续使用嵌入式工具窗口。
- Windows 普通窗口继续使用带系统标题栏的原生工具窗口。
- macOS/Linux 仅最大化但非系统全屏时保持现有规则。
- 点击已经打开的功能按钮，只把对应窗口调到最前。
- 关闭一个工具窗口不能关闭、替换或重置其他工具窗口。
- 切换原生/嵌入模式时，输入值、选择和打开状态不能丢失。

## 5. 设计原则

### 5.1 信息层级

- 主绘图区使用最高视觉权重。
- 当前数据集和当前 X/Y 列属于第二层信息。
- 状态提示、版本号和帮助文字属于第三层信息。
- 危险操作只在必要时使用红色，不让普通操作互相竞争。

### 5.2 简洁而非隐藏

- 高频功能直接显示。
- 低频功能可以进入菜单，但不能只能通过隐蔽手势访问。
- 不为了减少按钮数量而增加多层菜单。
- 工具窗口中的关键执行按钮始终容易找到。

### 5.3 一致性

- 统一按钮高度、圆角、内边距和文字基线。
- 统一输入框、数值框和下拉框高度。
- 统一区块标题、说明文字、错误文字和结果区域。
- 统一三个工具窗口的顶部、内容边距和滚动边界；底部操作区只在现有结构适合时使用。

### 5.4 跨平台

- 采用 Apple 风格的信息层级和留白，不复制假的 macOS 标题栏。
- 系统原生窗口保留各操作系统自己的标题栏和关闭按钮。
- 内嵌窗口只使用应用自己的轻量标题与“关闭”控件。
- 不假定 Windows 的“最大化”等于 macOS 的系统全屏。

## 6. 视觉规范草案

以下数值是实施起点，不是未经验证就必须固定的最终值。egui 使用逻辑点
（logical points），不是物理像素；所有尺寸都需要在不同 DPI 和系统缩放比例下验证。

### 6.1 间距

- 最小微间距：4 logical points。
- 同一组控件间距：8 logical points。
- 标签与输入区域间距：12 logical points。
- 功能区块间距：16 logical points。
- 大区块或窗口边缘间距：20–24 logical points。

所有布局优先从上述间距中选择，避免出现大量互不相关的 5、7、11、13 点。

### 6.2 字体

- 正文、数字和公式保持当前正常字号。
- 按钮文字不能为了容纳更多按钮而缩小。
- 小号文字只用于版本号和非关键说明。
- 标题只比正文高一个层级，避免多个过大的标题争夺空间。
- 禁用状态通过颜色和对比度表达，不依赖更小字号。

### 6.3 控件

- 同一级按钮保持相同高度。
- 主要操作、普通操作和危险操作使用三种明确层级。
- 只有真正需要强调的操作使用高对比填充。
- 下拉框箭头、输入区域和标签必须保持可辨认的点击范围。
- 键盘焦点、悬停、按下、选中和禁用状态必须清楚区分。
- 图标按钮必须同时提供 tooltip、可访问名称和足够点击区域。
- 不使用 SF Symbols 或其他受 Apple 平台许可限制的资源制作跨平台版本。

### 6.4 颜色

- 保持深色界面，不在本轮增加浅色主题。
- 背景、面板、悬浮层和输入控件建立有限的灰阶层级。
- 主要强调色使用克制的冷色，不覆盖曲线颜色的表达空间。
- 错误、警告、成功和选中状态使用语义颜色。
- 正文对比度目标至少 4.5:1，控件边界和焦点状态目标至少 3:1。
- 状态不能只依赖红色和绿色区分，还要有文字、形状或图标提示。
- 曲线调色板与导出图颜色暂不改变，避免把视觉改造混入数据表达变化。

## 7. 目标布局

### 7.1 顶部工具栏

最多分为三个逻辑组：

1. 文件：打开、导出图片、导出数据。
2. 分析：数据处理、曲线拟合。
3. 历史：撤销、重做。

要求：

- 同组按钮紧凑，不同组之间有明确留白。
- 文字按钮的边界清楚，不出现多个文字连成一句的情况。
- 宽度不足时优先收纳低频操作，不允许无规则换行破坏绘图区高度。
- 不改变现有按钮名称、含义和 Action。

### 7.2 左侧数据栏

- 宽屏下保持固定合理范围，不由文件名撑宽。
- 长文件名单行省略，悬停显示完整内容。
- 当前数据集、X 列和 Y 列形成一个连续且易扫描的区域。
- 复位视图与清空使用不同视觉层级。
- 操作说明降低权重，但不能因为窗口高度不足而覆盖核心控件。
- 窄屏继续使用现有适配逻辑，第一阶段不新增隐藏侧栏功能。

### 7.3 状态栏

- 状态信息保持左对齐并支持截断和悬停查看完整内容。
- 点击坐标固定在右侧，不因状态文本长度跳动。
- 版本号保持低权重，仅显示 `vX.Y.Z`。
- 状态栏与 X 轴标题之间保持稳定距离。

### 7.4 工具窗口公共外壳

三个窗口统一采用：

- 清晰但不过大的标题区。
- 有一致边距的可滚动内容区。
- 一致的关闭行为和错误信息位置。
- 原生窗口与嵌入窗口内容完全相同，仅窗口外壳不同。

本轮保持现有工具窗口初始位置和生命周期规则，不新增首次定位或自动错开。
用户移动后不得持续自动重定位，防止再次出现窗口抖动。窗口默认错开如有需要，
必须作为独立行为变化另行讨论。

### 7.5 数据处理窗口

按照当前真实顺序增加视觉分隔：对称/归一化、多项式背景、局部展平、
Savitzky–Golay 去噪、公式计算。只能添加区块标题和留白，不能移动控件，
也不能改成默认折叠区。

范围、曲线选择和覆盖/保留选项保持清晰可见。处理公式的解析错误继续使用
现有全局状态路径；字段级错误状态属于后续功能改动，不能在本轮新增。

### 7.6 曲线拟合窗口

- 数据源、当前曲线和多选目标保持在窗口前部。
- 拟合类型、范围、单位和参数分组清楚。
- 对已有 `settings.message` 进行清晰排版；不能解析错误字符串来推断字段，
  也不能新增字段级错误状态。
- 拟合结果保持公式、参数和 R² 的层次与自动换行。
- 长公式和大量参数不能被右侧裁剪。
- 所有文字保持正常字号。

### 7.7 数据导出窗口

- 先选择数据集/曲线，再选择列，最后选择合并或分开文件。
- 数据集与列列表分别拥有明确、可拖动的滚动区域。
- 全选、全不选不会改变列表布局或导致窗口退出。
- 底部始终显示选择摘要和导出按钮。
- 不恢复“当前/全部/多个”等重复入口。

### 7.8 绘图区

绘图区视觉修改放在最后一个独立阶段，并需要再次确认。第一轮只允许调整应用
外壳，不改变：

- 坐标轴格式和标签位置计算；
- 网格逻辑；
- 曲线、点和拟合线颜色；
- 图例 ID、顺序、名称和显隐逻辑；
- PNG 导出的视觉结果。

## 8. 平台和窗口验收矩阵

| 平台状态 | 工具窗口形式 | 必须验证 |
| --- | --- | --- |
| macOS 普通窗口 | 原生窗口 | 三窗口并存、移动、置顶、独立关闭 |
| macOS 系统全屏 | 嵌入窗口 | 保持现有初始位置、拖动无抖动、关闭按钮一致 |
| macOS 最大化但非系统全屏 | 保持现有模式 | 不误判为系统全屏、状态不丢失 |
| Windows 普通窗口 | 原生窗口 | 系统标题栏、× 关闭、窗口互不替换 |
| Windows 最大化 | 嵌入窗口 | 三窗口并存、拖动、置顶、状态保留 |
| Windows 真正全屏 | 嵌入窗口 | 与全屏判断一致、状态保留 |
| Windows 恢复普通窗口 | 原生窗口 | 状态和输入不丢失 |
| Linux 普通窗口 | 现有原生模式 | 编译、打开、滚动和关闭正常 |
| Linux 最大化但非全屏 | 保持现有模式 | 不扩大 Windows 特例 |
| Linux 真正全屏 | 嵌入窗口 | 打开、滚动和关闭正常 |
| 状态信息未知 | 原生窗口安全回退 | 不崩溃、不误用嵌入模式 |

当前 CI 没有 GUI 驱动，Windows 最大化、窗口层级和拖动行为必须在真实 Windows
人工验收，不能用“编译通过”代替。

## 9. 分阶段执行计划

### 阶段 0：建立 UI 基线

- 记录当前 `v0.3.7` 的普通窗口、窄窗口和 macOS 全屏截图。
- 记录三个工具窗口分别打开以及同时打开的状态。
- 记录长文件名、长公式、多参数和长列表场景。
- 运行完整测试、Clippy、Release 构建和导入导出检查。
- 所有截图写入仓库外的固定临时目录，并建立清单，记录提交、操作系统、
  系统缩放、逻辑窗口尺寸、测试数据和截图文件名；不提交机器路径或无用图片。

### 阶段 1：统一设计变量

- 在 `ui/theme.rs` 中集中现有颜色、字体、间距、圆角和控件高度。
- 先替换重复魔法数字，不改变布局结构。
- 验证正文、公式、按钮和数字字号没有缩小。

### 阶段 2：顶部工具栏与状态栏

- 建立三组工具栏层级。
- 统一按钮高度和基线。
- 处理窄窗口下的收纳规则。
- 在实现前明确哪些低频按钮可以进入溢出菜单；未获确认前不隐藏现有入口。
- 保持状态栏、版本号和坐标显示稳定。

### 阶段 3：左侧数据栏

- 固定宽度范围和长文件名截断。
- 对齐数据集、X/Y 标签与下拉框。
- 调整复位、清空和操作提示的视觉层级。
- 验证绘图区不会被侧栏或长文本挤压。

### 阶段 4：工具窗口公共外壳

- 统一内边距、标题区和滚动边界；不强制处理和拟合窗口使用固定底栏。
- 不改变窗口 ID、嵌入判断和置顶逻辑。
- 验证窗口移动后不会被布局代码反复重新定位。

### 阶段 5：逐个整理工具窗口

按以下顺序分别提交、分别测试：

1. 数据导出窗口。
2. 数据处理窗口。
3. 曲线拟合窗口。

每次只整理一个窗口，不同时修改另外两个窗口。

### 阶段 6：跨尺寸与多窗口修正

- 验证窄、矮、普通、最大化和系统全屏。
- 验证滚轮、滚动条、下拉菜单和键盘焦点。
- 验证三个工具窗口同时打开和交替置顶。
- 验证从最大化恢复普通窗口后的状态。

### 阶段 7：绘图区视觉评估

- 单独讨论网格、图例背景、曲线层级和当前曲线强调方式。
- 用户确认后才修改。
- 若修改导出图视觉，应作为独立功能变化记录，不能混在应用外壳改造中。

### 阶段 8：最终验收

- 运行全部自动检查。
- 由独立 agent 进行功能正确性验证。
- 在本地最新版 `.app` 上完成 macOS 人工验收。
- 用户确认本地 macOS 效果后，单独请求“推送测试分支”的授权。
- 获得授权后通过 GitHub Actions 构建 Windows 测试包，并在真实 Windows
  普通/最大化/真正全屏状态下人工验收。
- Windows 验收完成后，再由用户决定是否合并和发布；推送测试分支不等于发布。

## 10. 每阶段验证要求

### 自动检查

```sh
cargo fmt --all -- --check
cargo test --workspace --locked --all-features
cargo clippy --workspace --locked --all-targets --all-features -- -D warnings
cargo build --release --locked --package instplot-lite
cargo run --locked -- --check tests/fixtures/smoke.csv
```

还必须验证：

- 导出后重新导入的闭环测试。
- 数据处理数值与历史记录测试。
- 拟合参数、R²、来源关联和重复拟合替换测试。
- 曲线 ID、隐藏状态和窗口 ID 测试。
- 更新器现有测试。

### 人工界面检查

每个阶段至少在当前可用平台覆盖：

- 常规宽屏窗口。
- 接近允许最小尺寸的窄窗口。
- 高度不足、需要滚动的工具窗口。
- 长文件名、长公式、大量参数和大量列。
- 三个工具窗口同时打开。
- macOS 系统全屏。
- 100%、125%、150% 和 200% 系统缩放；Retina/高 DPI 与多显示器切换。

Windows 普通、最大化和真正全屏不要求每个小提交都单独推送测试，但必须在关键
用户确认点和最终阶段通过已授权的测试分支与真实 Windows 覆盖。

## 11. 重点回归场景

1. 全选数据集后再全不选，程序不能退出或崩溃。
2. 长列列表可以用滚轮和滚动条完整浏览。
3. 下拉菜单打开后可以滚动并选择底部项目。
4. 隐藏其他曲线后执行处理、拟合、撤销或重做，隐藏状态保持。
5. 同时打开数据处理和拟合窗口，移动任一窗口不抖动。
6. 最大化/全屏下重复点击工具按钮，只置顶对应窗口。
7. 长公式和参数列表自动换行，左右不被裁剪。
8. X/Y 轴标题、状态栏和刻度标签不重叠。
9. 导出 PNG 不包含工具栏、侧栏和状态栏。
10. 更新前后只有一个 `/Applications/InstPlot Lite.app` 被 Spotlight 索引。
11. Tab、Shift-Tab、方向键、Enter、Space、Esc 和撤销/重做快捷键保持可用。
12. 中文、长英文路径、负号、乘号、R² 和科学计数法不显示方框或被裁剪。
13. 从原生窗口切换到嵌入窗口并返回后，各工具窗口分别保持打开状态、输入、
    选择、滚动位置和键盘焦点；关闭其中一个不影响另外两个。
14. 嵌套滚动区使用稳定且互不冲突的唯一 ID，滚轮作用于指针所在区域。

## 12. 风险与控制方法

### 高风险

- 工具窗口原生/嵌入切换。
- 窗口 ID、控件 ID 和滚动区 ID 改变。
- 主界面高度变化影响绘图区和截图边界。
- 父滚动区与下拉弹层的输入冲突。
- 自动定位代码导致窗口拖动抖动。

控制方法：这些区域必须单独提交、保留原 ID、进行真实界面验收，并在失败时
立即回退到最近一个通过全部检查的提交。

### 中风险

- 工具栏响应式收纳。
- 左侧栏宽度和长文本处理。
- 工具窗口底部固定操作区。
- 错误提示位置和动态换行。

控制方法：为每种极端文本和窗口尺寸建立固定测试场景。

### 低风险

- 颜色 token。
- 圆角和分组间距。
- 不改变尺寸的文本层级调整。

即使是低风险修改，也必须运行完整自动检查。

### 性能边界

- 使用相同数据、相同窗口状态和相同采样方式记录启动后空窗口 RSS。
- 记录三个工具窗口同时打开后的 RSS、空闲 CPU 和是否持续重绘。
- 内存增长超过基线 10% 或 20 MiB 中较大者时必须调查；不能只用二进制大小代替。
- 空闲状态出现持续高 CPU 或无输入持续重绘时必须停止。

## 13. 停止条件

出现以下任一情况时停止继续改造：

- 任一数值、导出文件或拟合结果变化。
- 曲线、窗口或控件稳定 ID 被意外改变。
- 隐藏曲线重新显示。
- 工具窗口不能同时存在、无法置顶或关闭互相影响。
- 小窗口中存在无法访问的控件。
- 下拉框或滚动区无法操作。
- PNG 导出边界发生非预期变化。
- 为实现视觉效果需要重写算法或扩大共享可变状态。
- 只能在一个操作系统正常工作。

停止后先恢复最近一个稳定提交，再缩小改动范围，不能带着已知回归进入下一阶段。

## 14. 完成定义

只有同时满足以下条件，UI 改造才算完成：

- 用户确认整体视觉方向和主要窗口效果。
- 所有阶段的自动测试、Clippy 和 Release 构建通过。
- 数据结果、导入导出和更新行为不变。
- macOS 普通/全屏人工验收通过。
- macOS 最大化但非系统全屏不误判。
- Windows 普通/最大化/真正全屏及模式切换人工验收通过。
- Linux 普通、最大化但非全屏和真正全屏基本行为通过。
- 三个工具窗口和所有极端尺寸场景通过。
- 独立 agent 未发现可复现的功能回归。
- 本地 Spotlight 只索引最新版应用，安装可执行文件哈希已记录，实际运行进程
  来自 `/Applications/InstPlot Lite.app`。
- 最终确认后才提交发布相关改动和创建 Release。
