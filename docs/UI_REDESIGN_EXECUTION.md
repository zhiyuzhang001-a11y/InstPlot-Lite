## 1. 执行原则

1. 一次只处理一个视觉区域。
2. 每个工作包开始前确认允许修改的文件。
3. 先记录当前真实效果，再修改代码。
4. UI 绘制只返回现有 Action 或 Response，不新增业务副作用。
5. 每个工作包完成后运行自动测试和对应人工检查。
6. 每个稳定工作包单独提交，提交前不得包含下一阶段改动。
7. 当前工作包有任何回归时立即停止，不进入下一阶段。
8. 视觉缺陷和功能缺陷分开处理、分开提交。
9. 不用缩小字体、隐藏控件或取消功能来解决布局问题。
10. 不以 macOS 正常代替 Windows 验收，也不以编译通过代替 GUI 验收。
11. “测试通过”只证明没有功能回归，不等于视觉目标完成；每个确认点必须同时检查
    层级是否清楚、变化是否可见、是否仍是一排同权重灰色控件。
12. 应用外壳保持中性灰阶；除曲线和错误/危险状态外，不新增彩色填充。
13. 参考产品只是结构和规则来源；任何实现都必须通过现有 egui 组件完成，不把网页
    组件或另一套设计系统直接嵌入应用。
14. 组件使用语义 token，不直接散落 Carbon 色号或用途不明的 RGB 常量。

## 4. 标准自动检查

每个工作包至少运行：

```sh
cargo fmt --all -- --check
cargo test --workspace --locked --all-features
cargo clippy --workspace --locked --all-targets --all-features -- -D warnings
cargo build --release --locked --package instplot-lite
cargo run --locked -- --check tests/fixtures/smoke.csv
```

涉及图片导出边界时，还要运行：

```sh
cargo run --locked -- --open tests/fixtures/smoke.csv \
  --export-plot /tmp/instplot-ui-check.png
```

必须实际确认 PNG 存在、可读取、尺寸合理，并核对是否只包含绘图区。UI 改造可能
改变应用截图，但在绘图区视觉阶段开始前，导出的绘图 PNG 应保持原基准。
SHA-256 只允许在相同操作系统、渲染器、字体、逻辑尺寸、系统缩放和工具链下比较：

- 尺寸：860 × 703
- SHA-256：`dc8f012b5339985f7686eed9fad567287b8fe4a2527b7321a47df5e3b6f15fb1`

文本导出在格式和换行约定相同的环境中逐字节比较；XLSX 按工作表、单元格值、
类型和必要格式做语义比较，不能把 ZIP 容器字节哈希当作唯一正确性依据。

## 7. 视觉参考映射（返工前置规格）

本节是工作包 1–3 的固定映射保存位置，只记录借鉴规则，不保存第三方截图或资产。
“视觉确认”表示用户已确认总体方向；精确效果仍需在对应工作包的真实截图确认点通过。

### 应用外壳与 token

- 参考规则：Carbon Gray 100 的逐层变亮；Primer 的语义 token、对比度和焦点可见性。
- 当前问题：主题只有少量全局样式，缺少明确表面和完整交互状态；全局样式可能泄漏
  到绘图区。
- 目标几何/状态：绘图区、外壳、面板、控件、悬停/按下形成稳定层级；控件尺寸不因
  状态变化；焦点边界至少 2 logical points。
- 目标 token：`plot_bg_immutable` 与 `shell_bg` 分离，并使用工作包 1 列出的
  `panel/control/border/fg` 语义 token 和状态组合。
- 明确不采用：Carbon 蓝色强调、网页组件、Primer CSS、品牌色或字体资产。
- 验收：`M-01`、`M-03`、`T-01`、`T-06`，以及可复现的 4.5:1/3:1 对比度记录。
- 确认状态：总体方向已确认；实际色值在 WP1 截图确认中校准。

### 顶部工具栏与状态栏

## 提交和分支规则

- 当前工作位于独立的 `codex/ui-redesign` 分支；不得把 UI 试验合入
  `codex/code-consolidation`，也不得在用户重新确认开始前继续修改生产 UI。
- 每个工作包单独提交，提交信息使用 `style:` 或明确的 `fix:`。
- 纯验证记录使用 `docs:`。
- 不修改历史提交来掩盖失败阶段。
- 工作包失败时使用新的修复提交或可审计的 `git revert` 回到最近稳定状态；禁止
  `git reset --hard`、`git clean` 或任何可能删除用户文件的回退方式。
- 用户的未跟踪文件始终保持未暂存。
- 本计划本身可以本地提交，但不上传 GitHub。

## 停止与回退条件

出现以下任一情况时立即停止：

- 自动测试、Clippy 或 Release 构建失败。
- 任一导入、导出、处理或拟合结果改变。
- 曲线、拟合、窗口或滚动区域 ID 改变。
- 隐藏曲线重新出现。
- 全选/全不选导致崩溃或窗口退出。
- 工具窗口只能打开一个、互相替换或关闭联动。
- 窗口移动抖动或持续被自动重定位。
- 下拉框、菜单、输入框或滚动区域不可用。
- 小窗口存在无法访问的控件。
- 坐标轴标题、状态栏或刻度发生非预期裁剪。
- PNG 导出包含应用控件或边界变化。
- 只能通过改写业务逻辑才能继续视觉修改。

回退前先记录 `git status`、失败提交、复现步骤、影响范围和用户未跟踪文件；随后
使用新提交或 `git revert` 恢复，再决定缩小工作包或补充测试。
